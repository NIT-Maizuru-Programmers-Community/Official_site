# 困ったときの対処方法

エラーは、作業者を責めるものではなく確認が必要な場所を知らせるものです。分からないときは、下の「相談するときの情報」を添えて他の部員に聞いてください。

| 症状                           | 最初に確認すること                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `node` / `pnpm` が見つからない | インストール後にターミナルを開き直し、[セットアップ](getting-started.md)のバージョン確認を実行         |
| Node.jsの対応バージョンエラー  | `node --version` を確認。CIと同じ22系（22.13以上）にそろえる                                           |
| `package.json` が見つからない  | `cd Official_site` などでcloneしたフォルダーへ移動                                                     |
| パッケージ取得が失敗する       | 通信・プロキシを確認。証明書検証を無効化せず、ネットワーク担当へ相談                                   |
| `ERR_PNPM_OUTDATED_LOCKFILE`   | 正しいpnpm版か確認。依存変更を意図した場合だけ `pnpm install` を実行し、ロックファイル差分もPRへ含める |
| `pnpm dev` が終了しない        | 待機しているのが正常。表示されたURLをブラウザで開く。終了はCtrl+C                                      |
| 3000番ポートが使用中           | 自分が起動したサーバーを終了するか、`pnpm dev --port 3001` で起動し http://localhost:3001 を開く       |
| お知らせ・作品が表示されない   | `draft: true` は非表示。[コンテンツ更新ガイド](content-guide.md)を参照                                 |
| Prettierのエラー               | `pnpm format` → `git diff` で修正内容を確認                                                            |
| ESLint・型チェックのエラー     | 表示されたファイル・行番号を開く。無効化コメントを足す前に内容を確認                                   |
| テストで日付・slugが失敗       | 実在する日付、重複していないslug、空でない必須項目を確認                                               |
| 画像テストで失敗               | `public/images/` 内の実ファイルと `imageAlt` を確認。大文字・小文字も一致させる                        |
| pushで403 / Permission denied  | Gitの認証と書き込み権限を管理者に確認。GitHubの通常パスワードで再試行しない                            |
| `main` へのpushが拒否される    | 保護設定による正常な動作。作業ブランチからPRを作る                                                     |
| CI成功なのにマージできない     | 他者の承認、会話の解決、mainの最新化を確認。管理者の承認省略もCIは省略できない                         |

## インストール時の権限エラー

`npm install -g` がEACCESなどで失敗する場合は、Node.jsのインストール先や権限が原因の可能性があります。エラー全文とOSを部員に共有し、ユーザー用のNode.js環境を整えてください。分からないまま `sudo` や管理者権限で繰り返さないでください。

## CIの失敗箇所を読む

PRのChecksから `validate` を開き、失敗したステップを展開します。ログ末尾だけでなく、最初の具体的なエラーを探します。

ローカルでも該当するコマンドを実行し、修正後は同じPRへcommit・pushします。CIが再実行されます。文書だけのPRでもCIは動きます。

## マージ競合が出た場合

ファイル中の `<<<<<<<`、`=======`、`>>>>>>>` は、どちらの変更を残すか決まっていない印です。両方の意図を確認して統合します。判断できない場合はファイル名と競合箇所を共有し、元の変更者に相談してください。

このガイドの `git merge origin/main` を、変更をコミットした状態で開始した場合に限り、作業を中止するには `git merge --abort` を使えます。競合を隠すためにforce pushや `git reset --hard` を実行しないでください。

## 相談するときの情報

以下をIssueや相談先に伝えると状況を共有しやすくなります。トークン、個人情報、秘密情報は伏せてください。

```text
やりたいこと：
OS：
ブランチ名：
実行したコマンド：
エラーメッセージ：
期待した結果／実際の結果：
試したこと：
```
