# Notionへの開発ガイド同期

GitHubの`main`が正本です。Notionの「プロコン部公式サイトプロジェクト」配下に作成する同期専用ページは閲覧用の写しです。本文の変更はGitHubのPull Requestで行い、独自のメモは別ページに保存します。親ページ自体の本文は上書きしません。

## 対象と動作

`scripts/notion/config.json`にREADME、CONTRIBUTING、現行開発ガイド8件、この運用ガイドを列挙しています。AI指示ファイル、過去の計画書、検証記録、デザイン資料は対象外です。

`id`は文書の固定識別子、`path`はファイル名、`pageId`はNotionの同期専用ページIDです。ファイル名を変更しても`id`は維持します。通常同期はページを作成・削除しません。全ページの親・状態・管理用識別子を検査してから更新します。

- 同期対象間のリンクはNotionに向けます。見出しアンカー付きリンクと対象外ファイルはGitHubに向けます。
- 見出し、箇条書き、コード、表をNotion向けに変換します。コード例の文字列は書き換えません。生HTMLは改行タグ以外を拒否するため、HTML例はコードブロックに入れます。
- 各ページには元文書と反映コミット、同期識別子、内容ハッシュが表示されます。タイトルと変換結果が同じなら更新を省略します。
- 本文は全置換します。Notionだけの手動編集はサポートしません。同一ハッシュのページを強制更新する場合は、同期専用ページの`source-sha256:`行を削除して手動同期します。コメントの保持も保証しません。
- 子ページ・データベース削除の保護は解除しません。同期文書の中には子ページを追加せず、親ページ配下の別ページにメモを置きます。

## 初期設定

1. 同期先親ページを決め、[Notionの内部インテグレーション](https://developers.notion.com/guides/get-started/internal-connections)を同じワークスペースで作成します。コンテンツ・ページプロパティの読み取り、作成、更新に必要な権限を設定します。
2. 親ページの`•••` → 接続からアクセスを許可します。ページをWeb公開する必要はありません。
3. トークンを`NOTION_TOKEN`、親ページのUUIDを`NOTION_PARENT_PAGE_ID`として環境変数に設定します。トークンをソースコード、チャット、シェル履歴に貼らず、パスワードマネージャー等から設定してください。
4. ローカルで次を実行します。

```sh
pnpm install --frozen-lockfile
pnpm notion:dry-run
pnpm notion:setup
pnpm notion:verify
pnpm notion:sync
```

`notion:dry-run`はAPIを呼びません。未設定のリンク先はGitHubへ向け、`UNCONFIGURED`と表示します。`notion:setup`は不足する子ページを作り、対応表を1件ずつ保存します。作成応答が失われた場合も管理用識別子で既存ページを探して再利用します。重複があれば停止します。初期設定を同時に複数実行しないでください。

`notion:verify`は読み取りのみで、トークンと全同期先のアクセス・配置を確認します。`notion:sync`を再実行して`unchanged`となること、ページが増えないことを確認します。ローカル同期は作業フォルダの文書を使うため、未コミット変更があれば正式反映済みとは扱わないでください。

5. Notionで見出し・表・コード・リンクを確認し、生成されたページID対応表をPRに含めます。ページIDは秘密の認証情報ではありませんが、リポジトリの閲覧者に見える値です。
6. GitHubのSettings → Secrets and variables → Actionsで、Secret `NOTION_TOKEN`とVariable `NOTION_PARENT_PAGE_ID`を登録します。CodexのNotion接続だけではActionsの認証になりません。
7. `pnpm check`成功後、PR手順に従って導入します。導入前の認証確認は既存のCIワークフローを対象ブランチで手動実行します。手動実行時だけ`verify-notion`が動き、ページは変更しません。PRイベントにはSecretを渡しません。
8. 導入後、`main`で「Sync development guides to Notion」を実行し、反映と再実行を確認します。その後は対象文書や同期コードの`main`更新で自動反映します。

## 失敗時と運用

同期は直列実行します。429、読み取り・更新時の一時的な通信障害や5xxは最大4回試行します。作成時の通信切断・5xxは、重複防止のため自動再送しません。初期設定を再実行して既存ページを確認します。

- 401/403: トークン、接続権限、親ページの共有設定を確認します。
- 404や親ページ不一致: ページID、アクセス権、ページの移動・削除を確認します。自動では作り直しません。
- 一部失敗: 成功ページはロールバックしません。修正して再実行すると同一内容はスキップされます。
- 手動実行も`main`のみが書き込み対象です。同時実行は抑制し、開始時に最新の`main`を取得します。
- 対象文書を追加・改名する際は設定一覧とワークフローの対象パスを更新します。対象から外したページは削除せず、管理者が別途扱いを決めます。
- 同期停止はActionsでワークフローを無効にします。最終同期内容はNotionに残ります。

## 検証

```sh
pnpm test:notion
pnpm notion:dry-run
pnpm check
```

単体テストは模擬APIを使います。実トークンでの読み取り確認、実ページへの書き込み確認、Notion画面の目視確認はそれぞれ別に記録してください。

参考：[Markdown API](https://developers.notion.com/guides/data-apis/working-with-markdown-content)、[本文更新API](https://developers.notion.com/reference/update-page-markdown)。
