# Codex・Claude Codeで開発する

このリポジトリの「ハーネス」は、AIが参照する作業ルール、共通の検証コマンド、CIによる確認を組み合わせた開発の土台です。AIツールを自動起動したり、課金されるAPIをCIから呼び出したりする仕組みではありません。

## 指示の入口

| ツール      | 入口                 | このリポジトリの使い方                           |
| ----------- | -------------------- | ------------------------------------------------ |
| Codex       | ルートの `AGENTS.md` | リポジトリを作業場所として開き、共通ルールを参照 |
| Claude Code | ルートの `CLAUDE.md` | `@AGENTS.md` で同じ共通ルールを読み込む          |

共通ルールは [AGENTS.md](../AGENTS.md) だけで管理します。作業途中に入口を変更した場合は、新しいセッションで読み込みを確認してください。Claude Codeでは `/memory` で読み込まれるファイルを確認できます。

アプリ・CLIの認証やモデル選択は個人環境で行います。`.codex/config.toml` や `.claude/settings.json` に共有不要なモデル指定・権限の自動承認・フックは追加していません。個人の設定や会話スタイルを部の共通ルールへコピーしないでください。

## 始める前

1. [環境準備](getting-started.md)を済ませ、対象のリポジトリを開きます。
2. `pnpm install --frozen-lockfile` で依存を用意します。
3. `pnpm check:env` でNode.js・pnpm・依存導入・Gitの状態を確認します。環境を変更するコマンドではなく、問題があれば終了コード1を返します。
4. Issueや依頼に、目的・対象・変更してよい範囲・完了条件を記載します。
5. エージェントに「読み込んだプロジェクト指示と、今回使う検証コマンドを説明して」と依頼し、`AGENTS.md` が参照されていることを確認します。

Node.jsは22.13以上に対応し、CIとそろえる場合は22系を使用します。pnpmの指定版は [package.json](../package.json) が正です。doctorは設定値の簡易確認であり、ビルド成功やパッケージの完全性を保証するものではありません。

ブランチ名・コミット・PRタイトルは [CONTRIBUTING.md](../CONTRIBUTING.md) の命名ルールに従います。AIも `種類/担当者のGitHub名/概要` を使い、担当者には依頼者のGitHubユーザー名を指定します。不明な場合は確認し、認証中のアカウントから推測しません。`codex/`・`claude/`を特別な接頭辞にはしません。

## 共通コマンド

| コマンド            | 内容                                         | 使う場面           |
| ------------------- | -------------------------------------------- | ------------------ |
| `pnpm check:env`    | 環境と作業状態の診断                         | 初回・環境エラー時 |
| `pnpm check:quick`  | 整形確認・Lint・型チェック・テスト           | 編集中             |
| `pnpm check`        | quick＋ビルド＋7ページ・404の出力確認        | PR提出前とCI       |
| `pnpm check:static` | 生成済みHTMLの存在・非空・通常ファイルの確認 | 静的出力の切り分け |
| `pnpm format`       | 書式の自動修正                               | 整形チェック失敗時 |

check系は最初の失敗で止まり、ファイルの自動整形はしません。ただし型生成・ビルド・キャッシュなどの生成物は書き込みます。外部通信は通常の依存取得などに限り、エージェントの起動やGitHubへのpush・マージ・デプロイはしません。

CIのジョブ名 `validate` と管理者も迂回できない必須チェックは維持しています。CIでは依存インストール後に `pnpm check` を実行するため、人とAIで同じ検証ができます。

画面の見た目やアクセシビリティをすべて保証するコマンドではありません。UI変更ではブラウザ確認も行い、未実施ならその理由をPRに記載します。

## そのまま使える依頼例

### 小さな実装・修正

```text
AGENTS.mdとCONTRIBUTING.mdを読んでから作業してください。
目的：活動紹介の説明文を分かりやすくする。
対象：src/content/activities.ts のsummary。
完了条件：意味を変えず説明を短くし、pnpm checkが成功する。
既存の未コミット変更を保持し、変更理由と検証結果を説明してください。
今回はローカル変更まで。push・PR作成・マージ・公開は不要です。
```

### PRまで依頼する

```text
Issue #123の修正を、AGENTS.mdに従って実装してください。
担当者のGitHub名：HizKz（自分のユーザー名に置き換えてください）。
ブランチ名は fix/HizKz/123-fix-mobile-menu を使ってください（概要はIssueに合わせて変更）。
最新mainから作業ブランチを作り、目的外の変更を含めず、pnpm checkを実行してください。
変更をcommit・pushし、テンプレートに沿ったPRを作成してください。
GitHub Actionsのvalidateを確認し、失敗した場合は原因を直してください。
マージ・デプロイ・保護設定の変更は行わず、PRのURLと検証結果を報告してください。
```

### 読み取り専用レビュー

```text
このPRの差分とAGENTS.mdを読んでレビューしてください。
ファイル変更・コメント投稿・マージは行わないでください。
不具合、静的配信への影響、コンテンツの公開条件、必要な検証の不足を優先し、
問題があればファイル位置・根拠・修正案を説明してください。
```

## 変更を受け取る人が確認すること

AIの「成功しました」だけで判断せず、差分・実行ログ・GitHub Actionsの結果を確認します。PRのチェックボックスは検証済み、または対象外と確認した項目だけにチェックし、未実施の理由を残してください。

指示ファイルはセキュリティ境界ではありません。ツールの承認・サンドボックス・GitHubのRulesetが実際の制御を担います。ルールが守られない場合は権限を広げず、読み込まれた指示と依頼の範囲を確認します。

この仕組みの自動検証は共通コマンドとCIを対象にしています。Codex/Claudeのモデル応答が常に指示通りであることを保証する評価ではありません。
