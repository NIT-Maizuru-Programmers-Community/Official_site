# コードの構成と用語

## どこを変更するか

| 場所                   | 役割                         | 変更例                                         |
| ---------------------- | ---------------------------- | ---------------------------------------------- |
| `src/content/`         | 表示する情報                 | 活動紹介文、お知らせ、作品                     |
| `src/types/content.ts` | 情報の型（入力項目の決まり） | 作品に新しい項目を追加                         |
| `src/app/`             | ページと共通レイアウト       | `activities/page.tsx` が `/activities/` に対応 |
| `src/app/globals.css`  | 色・余白・文字サイズ         | スマートフォンの見た目を調整                   |
| `src/components/`      | 共通の表示部品               | ナビゲーション、作品一覧                       |
| `src/lib/`             | 共通処理とそのテスト         | 下書き除外、日付の検証                         |
| `public/`              | そのまま公開するファイル     | 写真、アイコン、OG画像                         |
| `.github/`             | GitHub上の運用               | CI、Issue・PRテンプレート                      |

`node_modules/` はインストールしたパッケージ、`.next/` と `out/` は生成結果です。手で編集したりコミットしたりしません。

## 使っている技術

Reactは画面を部品で組み立てる仕組み、Next.jsはReactのページ・ルーティング・ビルドを管理する仕組みです。TypeScriptは値や引数の型を確認し、Tailwind CSSとCSSで見た目を指定します。

データはTypeScriptファイルで管理します。CMSやDBの操作は不要です。ビルド時にHTMLへ変換する静的サイトなので、データを修正したら再ビルド・配信が必要です。

## コマンドの意味

| コマンド            | 何をするか                                 |
| ------------------- | ------------------------------------------ |
| `pnpm dev`          | 編集しながら確認するサーバーを起動         |
| `pnpm format`       | Prettierで書式を修正（ファイルを変更する） |
| `pnpm format:check` | 書式のずれを確認                           |
| `pnpm lint`         | ESLintでコードの問題を検査。警告も失敗扱い |
| `pnpm typecheck`    | Next.jsの型を生成し、TypeScriptの型を検査  |
| `pnpm test`         | Vitestでデータと共通処理を検証             |
| `pnpm build`        | 配信用HTMLなどを `out/` へ生成             |
| `pnpm preview`      | ビルド済みの `out/` をローカル配信         |

## GitHubの用語

- **clone**：リポジトリ（コードと履歴の置き場）をPCへコピーする。
- **branch**：変更を別々に進める作業単位。
- **commit**：変更内容を履歴に記録する。
- **push**：PCのコミットをGitHubへ送る。
- **Issue**：相談・作業・不具合を記録する場所。
- **PR**：ブランチの変更を取り込むためのレビュー依頼。
- **CI**：PRなどをきっかけに自動でチェックする仕組み。このサイトでは `validate`。
- **review / approve**：変更を確認し、取り込んでよいか判断すること。
- **Squash merge**：PRの変更を1つのコミットにまとめて取り込むこと。
- **conflict（競合）**：同じ箇所が別々に変更され、自動で統合できない状態。

操作は[最初のPR](first-pull-request.md)、掲載情報の変更は[コンテンツ更新](content-guide.md)へ進んでください。
